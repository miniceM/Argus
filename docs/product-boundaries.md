# Argus 产品边界与需求准入

**决策日期：2026-10-27。状态：已确认的产品方向与后续开发约束，不是新增功能验收报告。**

本文件定义产品范围，AGENTS.md 定义开发门禁，TECHNICAL_DESIGN.md 定义技术契约，OpenAPI 定义已交付接口。范围冲突时先按本文件收敛设计，不得绕过已有数据安全与质量约束。文档或 Issue 的新目标不会自动成为当前 API 能力；修改既有行为仍须单独实现、测试和兼容性评审。

## 1. 定位与价值假设

**Argus 是已有 Agent 服务的受治理评测桥接服务、持久化执行控制面与发布质量证据/门禁平台，不是另一套通用实验或发布运维平台。**

只回答五个问题：测的是哪个对象/版本/环境；按什么数据、评分与策略测；是否完整；为何得出结论；结论适用于哪次发布。

Langfuse SDK 的任务函数同样可以在业务进程之外调用任意语言的 HTTP 服务；Python 与 JS/TS 均有 Experiment Runner。普通实验、并发、故障隔离、比较和基础 CI 门禁不是 Argus 独占能力。Argus 的价值假设是降低多团队接入/维护成本，并统一执行恢复、证据采纳和发布约束；需要真实接入与故障验收证明，而非用功能数量证明。

官方参考（2026-10-27 核对；部署时仍需验证实际 Server/SDK 兼容性）：
- [Experiments via SDK](https://langfuse.com/docs/evaluation/experiments/experiments-via-sdk)
- [Experiments in CI/CD](https://langfuse.com/docs/evaluation/experiments/experiments-ci-cd)

## 2. 权威状态与集成边界

| 对象/生命周期 | 权威方 | Argus 允许保留的内容 |
|---|---|---|
| 业务逻辑、会话、模型与工具执行 | 业务 Agent | 调用契约、必要结果与外部证据引用；不重建业务 Runtime |
| 源码、镜像、部署实例 | Git/制品仓库/部署系统 | 被测身份引用、核验回执；注册版本号不自动等于远端制品已核验 |
| 日常 Dataset/Prompt 编辑、在线规则、Trace/Observation、实验探索 | 优先 Langfuse | 固定引用、此次实际使用的冻结用例/摘要和发布必需证据，不建双向编辑体系 |
| Launch、Attempt、恢复、取消与资源访问 | Argus | 持久化执行状态；不把 SDK 进程内并发当作持久化调度 |
| Release 结果、Snapshot、批准基准与 Gate 决策 | Argus | 不可变、来源明确、可审计的发布证据；Langfuse Score 是其单向幂等投影或受验证的外部输入 |
| 企业身份、Secret、网络和审批基础设施 | 企业既有设施 | 明确的权限点、Provider/身份适配、凭证引用和资源审计；不自建 IdP/Vault/网络控制器 |
| 部署、灰度、回滚、最终发布授权 | CI/CD 与审批系统 | 读取绑定版本/环境/策略的 Gate；不由 Argus 持有生产部署权 |

**一个对象只有一个可变权威源。** 冻结副本用于发布审计，不是重建 Trace Warehouse；外部当前值不能回填历史结果。每个外部 Score 必须验证所属 Project/Trace/Observation/Item、执行尝试及冻结采纳契约，不能按名称猜来源。

外部分数尚未返回属于评估等待/UNKNOWN，不能发布；已封存结果向 Langfuse 展示投影失败则属于同步问题，不得反向改写本地质量结论。历史引用的证据保留与法定删除/保留期要求必须显式协调，不能无期限复制敏感原文。

## 3. 四个核心模块

### 3.1 接入桥接

优先现有 SYNC_HTTP、Request Mapping、输出提取、credentialRef 与试跑。只对明确支持的接口契约承诺业务 Agent 不必内嵌 Evaluation SDK；不承诺任意服务只填 URL 即可接入。SDK 所在语言不约束被测服务语言。

OTel 是内部轨迹的可选来源，不是黑盒最终输出评测前置条件；不要求删除业务原有的可观测性 SDK。不支持的协议、复杂多轮或异步调用，必须有实际需求和明确执行/取消/结果契约才增加适配器。

桥接必须受授权目标、网络白名单、重定向/DNS/SSRF、TLS、凭证用途与项目资源范围约束。内网服务可作为明确授权目标，不能简单地以“禁所有私网”替代企业访问策略，也不能携带凭证访问任意用户 URL。

### 3.2 持久化执行

复用现有 Queue/Worker/状态机；接受任务、逐条执行、Attempt、恢复和取消均有持久化证据。仅重试评分与重调 Agent 分开；旧 generation、取消后的迟到结果、过期 lease 不得污染当前结果。

不承诺远端 exactly-once。超时不等于远端未执行；只有满足业务幂等/状态查询/隔离契约才允许自动重试有副作用调用，否则拒绝自动重放或进入明确的待处理状态。平台幂等键不能替代远端业务幂等。

不建设通用 DAG、任务市场或生产 Agent 调度平台，也不因模块边界提前拆分微服务。

### 3.3 版本与证据

冻结 Dataset/Agent/Evaluator/Runner，以及环境、适配配置、QualityPolicy、比较策略和批准基准；依据现有模型扩展，不建立第二套版本或结果类型。

区分“声明身份”与“经可信回执核验身份”。远端 URL 和手填版本号本身不能证明请求命中了指定部署制品。远端身份核验尚未交付时必须披露限制；正式发布所需的核验与失效策略由 #7/#6 落实，不能在文档中宣称已有保证。

冻结不意味着随机模型/知识库/外部工具完全确定性；记录可冻结部分与不可控依赖。重评生成新 revision/decision，历史快照不原地修改，不回退 latest，不把 UNKNOWN/缺失费用造为 0。

### 3.4 发布质量门禁

分开表达：质量结论、门禁判定、最终发布授权。仅 PASS 才满足 Argus 当前质量门禁；FAIL/UNKNOWN 不能因现有分数平均值高而通过。NOT_COMPARABLE 表达比较资格，不替代执行或质量状态。

目标证据绑定候选制品/版本、环境、Snapshot revision/digest、ReleasePolicy digest、批准基准和引擎版本；CI 必须核验其适用范围，而不是读取“最新绿色”。有效期、制品核验与决策校验由 #7 明确实现和验收；本文件没有新增这些 API。

优先接入既有审批系统。若有明确需求接受例外，只能生成授权、理由、适用范围/期限和审计记录独立的处置，不能把原始 FAIL/UNKNOWN 改成 PASS，不能自建通用审批流引擎。原始 Gate 保持不可变。

## 4. 保留、下沉、暂停与移除

| 处置 | 范围 |
|---|---|
| 核心保留 | 已支持服务接入、版本绑定、持久化执行、恢复隔离、外部评分严格采纳、冻结 Snapshot、批准基准、可比性、Gate 与 CI 证据 |
| 集成下沉 | Trace 全量浏览、普通实验趋势/对比、Dataset/Prompt 编辑、在线评估/告警/人工标注优先 Langfuse；SSO/Secret/审批/部署接企业设施 |
| 按需扩展 | 最小轨迹证据与违规定位、特定新适配器、额外 CI Provider；必须有消费者、场景和验收 |
| 暂停默认扩建 | 自建通用 Trajectory LLM Judge/校准平台、通用轨迹浏览器、完整规则市场、任意协议兼容、复杂多租户运营与计费 |
| 移出活跃产品承诺 | 通用 DAG/审批设计器、生产部署/灰度/回滚执行器、第二套 Dataset/Prompt/Trace 分析产品、生产失败挖掘与在线监控闭环 |
| 兼容维护 | 已有接口、确定性轨迹规则、安全/来源验证、i18n 补丁和真实夹具；暂停新范围不允许删除质量保护或绕过现有 CI |

最小轨迹能力是可选发布证据：无内部观测时最终答案仍可评。若冻结策略显式要求某轨迹证据，缺失必须 UNKNOWN；optional 诊断缺失不能污染未要求该证据的必需完成度。不能通过把 required 改成 optional 规避失败。

## 5. 开发需求准入（人工评审门禁）

每个新增 Issue/PR 必须说明：
1. 具体消费者/业务场景，以及服务于“接入成本、执行可靠性、证据可信度、发布风险”中的哪项。
2. 复用 Langfuse/企业设施/现有 Argus 模块为何不足；不要以“别人没有”或“平台更完整”为理由。
3. 权威状态归属、跨系统读写方向，以及明确非目标。
4. 当前事实、目标方案与验收证据分别是什么；版本/环境、失败/恢复、权限/敏感数据如何验证。
5. 运维/维护成本与退出方式；没有需求则保留诊断/延期，不进入 v1.0 必选依赖。

这是需求与评审门禁，不是本次新增的自动 CI 检查。行为变更仍执行 AGENTS.md 的自动测试与 make validate；不得因范围收敛删除安全/回归测试。

## 6. 收敛后的近期闭环与验收

主线：登记已有 HTTP 服务 → 明确被测身份/环境 → 固定用例/评分/策略 → 持久化执行与恢复 → 严格采纳结果 → 封存 Snapshot → 对比批准基准 → CI 核验并消费质量门禁。

| 验收 ID | 必须取得的行为证据 | 主要跟踪 |
|---|---|---|
| B1 | 已支持 HTTP 服务不内嵌评测 SDK；远端身份声明/核验限制明确 | #7；已有接入复用 |
| B2 | Worker 中断、重试、取消、迟到结果不丢任务/不串尝试；有副作用不盲目重放 | #7 与既有 Runtime 回归 |
| B3 | 缺分、错误、来源不明、必需证据缺失均不误 PASS | #7；#49/#212 历史交付复用 |
| B4 | Dataset/外部评分规则变化不改历史快照；重评新修订 | #7；既有 Snapshot 回归 |
| B5 | 版本/制品/环境/策略错配、无效或过期判定不能被 CI 复用 | #7（待补正式发布身份/有效期契约） |
| B6 | 未授权操作、越权目标与凭证/PII 泄漏被阻断且有安全审计 | #6、#31 |
| B7 | 有明确轨迹需求时验证来源/完整性；不要求轨迹的 HTTP-only 评测不被阻断 | #5/#127–#132 按需，不阻塞普通闭环 |
| B8 | 例外处置不篡改原始 Gate，发布仍由外部 CI/CD/审批授权 | #6/#7；无例外功能时明确不支持 |

v1.0 以主线和必需安全/证据场景的真实验收为准，不以某张 Issue 的 closed 状态或完成全套 S4–S6 功能清单代替。#49/#212 已关闭只证明原范围交付，不证明 B1–B8 已验收。
